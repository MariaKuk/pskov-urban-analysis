# Псков — выполненная практика 2

Дата: 23.11.2026. Расчёты и локальный дашборд выполнены в Codex по прямому
поручению пользователя. Это отличается от рекомендованного порядка преподавателя,
где студент самостоятельно запускает ячейки. Публикация в GitHub не выполнялась.

## Открыть результат

- `dashboard.html` — готовая интерактивная страница. Открывается двойным щелчком
  в браузере; для самой карты кварталов интернет не нужен. Подложка OSM включается
  отдельно и требует интернет.
- `examples/pskov.ipynb` — выполненный ноутбук с кодом, таблицами, картами и пояснениями.
- `REPORT.md` — краткие результаты, интерпретация и ограничения.
- `results/pskov/dashboard_metric_coverage.csv` — все 15 показателей: раздел ноутбука,
  элемент дашборда и поле GeoJSON.
- `results/pskov/audit/quality-report.json` и `dashboard-browser-check.json` — проверки.

## Что получилось

933 квартала в административной границе Пскова. Показатели застройки сохранены для
всей территории; матрица времени, школьная обеспеченность и транспортная доступность —
для 781 квартала, покрытого основной связной частью готового автомобильного графа.
152 квартала не получили транспортной оценки; это пропуски, а не нули.
Подробная причина и правило включения: `reference/pskov-change-log.md`.

Население, отсутствующая этажность и вместимость школ оценены модельно.
Это не официальная статистика и не проверка нормативной пешей доступности школ.

## Повторить на сохранённых данных

Откройте эту папку в VS Code. В терминале проекта:

```bash
source .venv/bin/activate
```

Для просмотра ноутбука выберите ядро «Псков (Python 3.12)» или `.venv/bin/python`.
Ячейки уже выполнены. Повторять их только ради просмотра не требуется.

Чтобы повторить весь расчёт, можно выполнять ячейки сверху вниз или запустить:

```bash
python tools/run_pskov_notebook.py --launched-by student
python tools/audit_pskov_results.py
python build_dashboard.py
open dashboard.html
```

Загрузки используют проверенный кэш. Скрипт запуска сохраняет ноутбук после каждой
ячейки и резервную копию предыдущего файла. При ошибке не продолжайте расчёт;
передайте текст ошибки. Для полного обновления источников сначала сохраните
копию проекта, затем следуйте разделу 0 ноутбука — не смешивайте версии данных.

Только пересобрать HTML из готовых результатов:

```bash
python build_dashboard.py
```

Сборщик страницы не скачивает данные и не пересчитывает модели. Он читает готовые
GeoJSON, таблицы, манифест и прошедшую аудит сводку. Итог — один `dashboard.html`.

## Структура и окружение

- `data/pskov/raw` — исходные GeoJSON, ответы Overpass, граф и метаданные.
- `data/pskov/processed` — кварталы, здания, школы, привязки, исключения и матрица NPZ.
- `results/pskov` — итоговые показатели, CSV, GeoJSON, сводки, аудит.
- `reference` — пример BlocksNet, источники, журнал исправлений и выполнения.
- `tools/notebook_sources/pskov.py` — редактируемый исходник ноутбука; это не команда запуска.
- `assets` — шаблон дашборда и локальная библиотека Leaflet с лицензией.

Python 3.12, BlocksNet 1.0.0a9. Зависимости — в `pyproject.toml`; фактически
установленные версии — в `requirements-observed.txt`. Это снимок macOS arm64,
не универсальный файл блокировки для любой ОС. На Apple Silicon нужны системные
библиотеки `libomp` и `cbc`; в этом проекте они уже установлены.

`tools/build_pskov_notebook.py` пересоздаёт ноутбук из исходника без результатов
и откажется перезаписать выполненный файл. `--replace-executed` разрешает замену
только с резервной копией. Не используйте сборщик вместо команды выполнения.
